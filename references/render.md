# 生成 pptx

大纲经用户认可、用户要成品文件时读这份文件。做法是：选定一套模板和它的风格文件，用 `scripts/pptkit.py` 在模板上逐页生成。标题、导语、结论条这些固定位置由模板管，图示由 pptkit 画，页面代码里不写颜色值、不写字体名。

需要 Python 和 python-pptx。运行环境里没有时先告诉用户，由用户决定是否安装。

## 一、选模板

用户给了模板或旧稿，按第三节做。用户没给，从 skill 自带的三套里选一套，在回复里说明选了哪套、为什么，用户可以要求换。

| 模板 | 样子 | 适合 |
|---|---|---|
| `assets/templates/航线.pptx` | 深蓝封面配航线网络图，正文白底，用细线和表格承载内容 | 向上汇报、决策请示、方案评审 |
| `assets/templates/极光.pptx` | 靛蓝到珊瑚色的渐变底图，正文是带柔和阴影的白色卡片 | 客户方案交流、培训、现场讲 |
| `assets/templates/朱砂.pptx` | 米白、墨黑加一个朱红圆，全部是可编辑的矢量图形 | 分析调研、观点鲜明的汇报 |

每套模板有五个版式：封面、目录、章首页、正文、结尾。同名的 `.json` 是它的风格文件。

## 二、写生成脚本

```python
import sys
sys.path.insert(0, "<本 skill 的目录>/scripts")
from pptkit import Deck

d = Deck("<本 skill 的目录>/assets/templates/航线.pptx")      # 风格文件默认取同名的 .json
d.page("cover", kicker="工作汇报", title="第一行\n第二行", subtitle="副标题", meta="单位　2026 年 11 月")
pg = d.page("agenda", title="汇报内容")
x, y, w, h = pg.body                                         # 主体区的位置和大小
pg.bullets(x, y, w, [("章名", "这一章的论点"), ...])
d.page("section", number="01", title="章名", lead="章首预告")
pg = d.page("content", chapter="第一章 章名", title="页标题", lead="导语", conclusion="结论条",
            source="出处：……", notes="讲述要点")
x, y, w, h = pg.body
bottom = pg.stats(x, y, w, [("4 轮", "流程全部走通"), ("0 次", "正式对比")])   # 每个图示返回它的下边缘
pg.matrix(x, bottom + 0.15, w, ["轮次", "做法", "结果"], rows)
d.page("closing", title="请求事项", subtitle="补充说明")
d.save("成品.pptx")
```

- 封面、章首页、结尾页没有主体区，只填标题这几栏，不在上面画图示。结尾要逐条列出的请求事项，放在结尾页前面的一张正文页上。
- 大纲里没有的栏不传，例如没有导语就不写 `lead`，没有结论条就不写 `conclusion`。模板上对应的位置会被去掉，主体区随之变大。不为了把位置填上而现编一句。
- 大纲里写了 `columns` 和 `cells` 的块，按“对象乘方面”来画：`name` 是第一列或阶段名，`cells` 是各方面的内容，`columns` 是表头或行名。带 `mark` 的那一项用 `hi_col`、`current` 或 `hi` 突出。
- 一页放多个图示时，用上一个图示返回的下边缘接着往下排，或者把主体区左右分开各放一个。
- 字号不用自己调。一页上的图示共用一档字号，pptkit 按主体区的高度自动选：内容少就放大，内容多就缩小，范围是风格文件字号的 0.92 到 1.25 倍；架构图、流程图、能力地图这三种密集的图可以缩到 0.72 倍，边距也跟着收紧。每画一个图示，这页前面的图示会按新的一档重画，间距不变。图示下面还要用基础函数画东西时，给图示传 `leave=要留的高度`（英寸）。
- pptkit 的用法都在本文件里，不必读它的源码。
- 封面标题超过一行时，在意群的分界处用 `\n` 断行。
- 字号缩到最小一档仍放不下的页，`save()` 会打印是哪一页、多出多少。打印出来的每一条都要处理，处理办法见第五节。

大纲的 `component` 对应的画法：

| 大纲里的图示 | pptkit 的方法 | 数据 |
|---|---|---|
| 对比表、对照表、矩阵 | `matrix(x, y, w, 表头, 行, colw, hi_col)` | 行可以直接传大纲里的 `items`（`name、cells、mark`），表头传 `columns`；也可以每行写成一组文字，第一列可写成 `(编号, 名称)`。`hi_col` 是要突出的列，只在确有一列是听众要先看的时候传（例如推荐方案、我们的做法），否则不传；带 `mark` 的行自动加底色 |
| 分层架构、阶梯图、嵌套 | `layers(x, y, w, 各层, side)` | 每层 `no、name、desc、sub`；`side` 是右侧与各层对齐的一栏 |
| 分阶段流程、时间轴 | `stages(x, y, w, 各阶段, 行名, extra)` | 各阶段可以直接传大纲里的 `items`（`name、cells、mark`），行名传 `columns`。上面是进度轨道，下面每列一个阶段、每行一个方面；带 `mark` 的是当前阶段 |
| 步骤流程、因果链 | `flow(x, y, w, 各步)` | 每步 `name、desc` |
| 对照栏、分组对照栏 | `compare(x, y, w, 各栏, hi)` | 每栏 `title、items` |
| 卡片组、分组卡片 | `cards(x, y, w, 各项, cols)` | 每项 `tag、title、sub、body` |
| 分层架构图 | `arch(x, y, w, 各层, left, right, legend)` | 各层可以直接传大纲里的 `items`：每层 `{"group": 层名, "items": [...]}`，层内的每项是文字、`{"name", "mark"}`，或再一个分组 `{"group", "items"}`。`left`、`right` 是贯穿各层的侧柱 `{"group": 名称, "items": [可无]}`。`legend` 是图例，如 `["本期新建", "已有"]`，`mark` 写图例里的一项 |
| 流程图、泳道流程图、判断树 | `flowchart(x, y, w, 节点, lanes)` | 节点按流程先后列出，每个 `id、name、kind（开始、步骤、判断、结束）、to、lane、desc、mark`；`to` 是去向，写 `"id"` 或 `("id", "线上的字")`，指向前面的节点就是回退线。`lanes` 是泳道名称的列表，给了就画成泳道。列和行自动排：交给另一条泳道的那一步排在正上方或正下方，同一条泳道里并行的分支上下排开，不要自己指定列和行，也不要为了放得下去掉泳道 |
| 能力地图、清单全貌 | `grid(x, y, w, 各组, cols, legend)` | 每组 `{"group", "items"}`，`items` 的每项是文字或 `{"name", "mark"}`；各组的格子上下对齐。`legend` 如 `["已上线", "建设中", "规划"]` |
| 大数字 | `stats(x, y, w, [(数字加单位, 含义)])`、`callout(x, y, w, 数字, 含义)` | 最多四个 |
| 短条目清单 | `chips(x, y, w, 栏名, 条目)` | 每条不超过 12 个字 |
| 目录 | `bullets(x, y, w, [(章名, 论点)])` | 只用于目录页 |

这三种图直接把大纲里的数据传进去，排列、走线、字号都由 pptkit 处理。`save()` 会打印它发现的问题，例如 `mark` 写的词不在图例里、流程图列数太多，按打印的改法处理。

这三种复杂构图的容量：架构图 3 到 6 层，全图 50 格以内；流程图 16 个节点以内，一行最多 8 个，判断节点的名称不超过 10 个字；能力地图 60 格以内，每格不超过 8 个字。超出时按阶段或按子系统拆成两页，第一页放总图，第二页放其中一块的展开。

目录之外的图示（闭环、树、四象限、截图标注、原生图表等）用基础函数画：`pg.text`、`pg.box`、`pg.card`、`pg.line`、`pg.badge`、`pg.pill`、`pg.table`、`pg.group`，连线用 `pg.connect(形状a, 连接点, 形状b, 连接点, kind)`（连接点 0 上、1 左、2 下、3 右；`kind` 有 `straight`、`elbow`、`hv`、`vh`），连接符画不出的走线用 `pg.polyline([(x, y), ...])`。构成和容量见 `components.md`。画的时候守四条：

1. 颜色只写角色名：`primary`、`accent`、`text`、`muted`、`line`、`tint`、`surface`、`on_primary`。
2. 先画底，后画字。一个图示的底和字用 `pg.group` 组合在一起并起名。
3. 高度用 `pg.paras_h(段落, 宽度)` 量出来，底跟着字走。
4. 函数最后返回图示的下边缘，并在调用后把 `pg.bottom` 更新为较大值，这样超出检查才有效。

## 三、用户给的模板

用户的模板、它的风格文件、生成的成品都放在用户的工作目录，不放进 skill 目录。

1. 运行 `python <本 skill 的目录>/scripts/template_info.py 模板.pptx`，再运行 `preview.py 模板.pptx` 看它每一页的样子。
2. 在工作目录写一个风格文件，说明每种页面角色怎么来。三种来法：
   - 版式里有占位符：`{"layout": "版式名", "fields": {"title": {"ph": 0}, "lead": {"ph": 13}}}`，编号取 template_info 列出的占位符编号。
   - 版式里没有占位符、文字放在示例页上（封面和章首页常见）：`{"sample": 1, "fields": {"title": {"shape": "文本框 4"}}}`，表示复制第 1 张示例页，把名为“文本框 4”的形状里的字换掉，格式保留。几章的章首页背景不同的，写成 `"sample": [2, 3, 4, 5]`，生成时用 `pick` 指定第几张。
   - 正文页只有底图和标志：`{"layout": "版式名", "body": [x, y, w, h], "fields": {"title": {"box": [x, y, w, h], "size": 24, "bold": true, "color": "primary"}}}`，在固定位置放文本框。位置避开模板的标志和页脚，量 template_info 给出的坐标来定。
3. 颜色和字体以 template_info 的统计为准。主题色是 Office 默认值的模板，品牌色取“用得最多的颜色”，在风格文件的 `colors` 里写色值；字体在 `fonts` 里写模板实际用的字体。不引入模板里没有的颜色。
4. 先做三页试样：封面、一张章首页、一张内容最多的正文页。渲染出来和模板的示例页并排看，确认标题位置、颜色、字号与模板一致，再做全稿。
5. 模板的固定元素（标志、页脚色条、背景图）一律保留。pptkit 在示例页换字时，如果新文字比模板示例长出一行，会打印提醒，按提醒缩短文字。

风格文件的完整例子见 `assets/templates/航线.json`；`fonts` 一栏在自带模板里省略了，表示跟随模板的主题字体。

## 四、密度和版面的要求

- 每页一个主图示，最多再加两个辅块，例如一排大数字、一组短条目、一个强调数字。
- 密度为中高或高的页，主图示的每一项要有第二层信息：说明、数据或例子。只有名称的图示装不下“会后还要翻”的材料。页面上至少有一处数字或出处。
- 密度为低的页只留一个图示或一个数字，文字不超过 80 个字。
- 图示的大小跟着内容走。内容少就让图示小，贴着主体区的上沿放，留白留在下方；不拉大图示去填，不把图示往下推，也不为了填满在页面代码里加内容。一页下方空出一半以上，说明大纲里这页内容太少，回到大纲补第二层信息或与相邻页合并。
- 每页只有一处最醒目：一个大数字、当前所在的阶段，或表格里突出的一列。
- 页标题控制在一行以内。结论条也控制在一行以内，放不下就删到只剩那一句新的话。
- 证据和出处要上页面：数据进图示，出处写在 `source` 里。
- 结论条、卡片、标题都不加单侧的色条，也不加标题下划线。要突出就用整块底色或加粗。
- 页面上只放大纲里有的内容。不加“说明”“备注”这类栏名，不在图示下面加解释文字，不给每一项贴状态标签；表头和行名各写一次。完整的清单见 `page-plan.md` 第三节。

## 五、检查和交付

1. 处理 `save()` 打印的每一条超出提醒。处理顺序：把这页拆成两页，并回到大纲补上新页的标题；把次要的行或次要的方面移进讲述要点；换成更省地方的图示。不把每一格压成短语来换地方，压短以后页面放得下，但听众要的具体内容没有了。
2. 运行 `python <本 skill 的目录>/scripts/preview.py 成品.pptx`，得到逐页图片和一张总览图。逐页看：文字有没有被盖住或超出；同类页的标题是否在同一位置；有没有空的框；颜色是否只有模板里的那几种。
3. 总览图上看整份：封面、章首页、正文、结尾是否像同一份材料；有没有连续三页用了同一种图示。
4. 交付时告诉用户：用了哪套模板；哪些页的图示是用基础函数另画的；本机预览用的字体和成品里的字体不同时，说明字宽可能略有出入；没有在 PowerPoint 里打开验证过的，照实说。
