# 第 4 层 块：先判关系，再选图示

这一层定每个内容块的五样东西：要表达什么（`says`）、块内各项之间的关系（`relation`）、各项内容（`items`）、建议的图示（`component`）、证据和出处（`evidence`）。

页内内容被画成并列的要点或卡片，是因为并列不需要判断。这一层要求先回答“这几项之间是什么关系”。

## 一、关系的判定顺序

对一个内容块，按下面的顺序问，第一个回答“是”的就是它的关系。

| 顺序 | 问句 | 关系 |
|---|---|---|
| 1 | 整块只为突出一个数字或一句话吗 | 强调 |
| 2 | 内容是界面、文件这类原件吗 | 实物 |
| 3 | 要比较数值吗 | 数量 |
| 4 | 每一项都要同时按两个维度看吗 | 交叉 |
| 5 | 是按条件走不同的路吗 | 分支 |
| 6 | 调换各项的次序，意思会变吗 | 会变：最后一步回到第一步是循环；前一项导致后一项是因果；其余是顺序 |
| 7 | 有上下层，或谁包含谁吗 | 层级 |
| 8 | 是两三个对象按同一组标准作比较吗 | 对比 |
| 9 | 是多项归到一项，或一项展开成多项吗 | 汇聚 |
| 10 | 以上都不是 | 并列 |

词表是默认用词。不够用时写“其他：……”并说明。

`relation` 描述的是 `items` 最外层各项之间的关系。内容分了组时，它指组与组之间的关系，不因为分了组就改成层级。

## 二、容易判错的五组

| 容易混的两种 | 怎么分 | 例 |
|---|---|---|
| 并列和顺序 | 调换次序后意思变不变 | “开工前要确认的五件事”调换后不影响，是并列；“上线的五个步骤”是顺序 |
| 顺序和分支 | 有没有“如果……就……” | “目标明确进开发，不明确先探索”是分支 |
| 顺序和因果 | 前一项是不是后一项的原因 | “集中提交造成积压，积压造成延误”是因果 |
| 并列和层级 | 内容有没有分组 | 八类风险归成三组后是两层，图示要能表达分组 |
| 对比和交叉 | 对象多不多、维度多不多 | 两个方案比三点是对比；六个项目对八项能力是交叉 |

## 三、关系对应的图示

| 关系 | 候选图示 |
|---|---|
| 顺序 | 步骤流程；时间轴；阶梯图；有判断和回退时用流程图；多角色时用泳道流程图 |
| 分支 | 流程图；判断树 |
| 循环 | 闭环图 |
| 层级 | 分层架构图；能力地图；树；嵌套容器；分组卡片 |
| 对比 | 对照栏；对比表 |
| 交叉 | 矩阵；四象限；对照表 |
| 因果 | 因果链；问题、原因、对策三段 |
| 汇聚 | 中心辐射；汇聚图 |
| 数量 | 原生图表，见下 |
| 实物 | 大截图加编号标注 |
| 强调 | 大数字；引言 |
| 并列 | 卡片组；图标行 |

数量关系按要说的话选图：占比用饼图或堆叠条形图；项目之间比大小用条形图；随时间变化用柱形图或折线图；分布用直方图；两个变量的关系用散点图。

候选都不合适时，`component` 写“其他：……”并说明画法。

连续几个块用了同一种图示时，回到关系重新判断一次。关系确实相同就保留，可以换一种候选。

## 四、每一项怎么写

一项只有一个短语，排到页面上就是一个空框。几个对象各有两三个方面要说时，把方面的名称写进 `columns`，每项写成 `name` 加 `cells`：

```json
"columns": ["做什么", "进入下一步的条件"],
"items": [
  {"name": "第 1 个月 并行比对", "cells": ["系统与人工各审一遍，逐单比对结论", "结论一致的比例达到约定值"], "mark": "当前"},
  {"name": "第 2 个月 小范围切换", "cells": ["两个部门改用新流程，其余部门照旧", "差错单据数不高于人工审核时期"]}
]
```

- 方面怎么选、格子怎么填，见 `page-plan.md` 第一节。
- `mark` 标出要先被看到的那一项，一个块里最多一项。
- 只有一个方面要说时，写成“名称：说明”的一句话即可，不必用 `cells`。
- 方面的名称只在 `columns` 里写一次，不在每格里重复。

流程图、分层架构图、能力地图这三种图要把全貌画出来，写法见 `page-plan.md` 第四节。

## 五、分组

块内超过 5 项时先分组。组名写成概括，再列组内的项：

```json
"items": [
  {"group": "事前", "items": ["规则逐条确认", "并行期比对结论"]},
  {"group": "事中", "items": ["超限单据转人工"]}
]
```

分组不改变关系，只是给图示加一层。在该关系的候选图示前加“分组”二字即可：

| 组与组的关系 | 分组后的图示 |
|---|---|
| 并列 | 分组卡片 |
| 顺序 | 分阶段流程 |
| 对比 | 分组对照栏 |
| 因果 | 分组因果链 |
| 层级 | 树；分层架构 |

什么时候分组，看分完以后是否更清楚：

- 一组并列的内容超过 6 项，先试着分成两到四组。组名是概括，能让听众先记住几个大类。
- 步骤、表格行、数据点、截图的项数由事实决定，上限放宽到 9 项，不为凑数而合并；多时按阶段分组，组内保留每一项。
- 来源本身就是一份固定清单、分组会显得生硬时，不分，在 `waivers` 里说明。
- 分出来的组只有一项，或者组名是硬凑的，说明这组内容不适合分，退回不分。

## 六、证据

- 每个带论点的页至少有一条证据。证据的类型有事实、数据、案例、截图、原文引用。
- 证据写明出处。对外材料尤其如此。
- 依据是推断时照实写，并在页面上注明是推断。
- 为说明问题而编的例子、自己归纳出来的示意，在页面上标明“示意”，不写成实测结果或真实产出。
- 没有出处的数字，删掉，或标明是建议值并写明怎么测。
- 与论点无关的材料不上页面，需要保留的进附录。
- 只用拿到的材料。材料里引用了但没有提供的文件，可以在页面上指路，不转述它的内容。

## 七、这一层的自检

对每个块问三件事：

- `says` 这句话，图示画出来以后看得出来吗。
- 把图示换成一列要点，会不会丢信息。不丢的话，关系多半判成了并列，重判一次。
- 各项的写法是否平行：同一类词开头，长短相近。
