# 第 2 层 章：章内怎么组织

这一层定每章的五样东西：章内组织模式（`pattern`）、各页之间的关系（`relation`）、章首预告（`opens`）、章末收束（`closes`）、页的清单（每页的 `role` 和 `title`）。

章内的页如果只是同类东西排成一列，章就是平的。办法是先选一种组织模式，让每页在章里有明确的位置。

## 一、章内组织模式

| 模式 | 适合 | 页的排法 |
|---|---|---|
| 总览展开 | 一组同类内容：功能、能力、建议、规则 | 一页总览列出全部并分组，随后逐组或逐项展开 |
| 论点证据 | 一个结论需要多份证据 | 一页给出结论和证据的汇总，随后每页一条证据 |
| 问题对策 | 说明为什么这样做 | 现象、原因、对策，需要时加效果 |
| 逐项对应 | 前文提出了几个问题或目标 | 每页回应一项，导语点明回应的是哪一项 |
| 场景循环 | 多个业务场景或功能 | 每个场景按“遇到的情况、做法、例子”走一遍，各场景结构相同 |
| 对比选择 | 要在几个方案之间取舍 | 评价标准、各方案、比较、推荐 |
| 时间推进 | 历程、计划、路线 | 过去、现在、下一步，或按阶段 |
| 概念讲解 | 让听众学会一个概念或操作 | 是什么、例子、怎么做、易错点 |

一章可以组合两种模式，例如先“问题对策”再“总览展开”。都不合适时写“其他：……”并说明排法。

选定模式后填 `relation`：章内各页之间的关系，用块层的同一张词表（见 `L4-block.md`）。

## 二、章首和章末

三页以上的章要有两句话：

- `opens`：本章回答什么问题、分几部分讲。
- `closes`：本章讲完得到什么结论。

放在哪里由场景档定：`opens` 可以在章首页或分隔页上；`closes` 可以在小结页上，也可以在本章最后一页的结论条里。

上一章的 `closes` 和下一章的 `opens` 要接得上。接不上说明两章之间缺一步，或者章的先后排错了。

## 三、小结页

小结页只在一章内容多、需要停下来回收时才设。短的章用结论条收束。

小结页不重复罗列前面各页的要点。做法是回到本章的总览图，标出讲过的部分，加上那句收束。各章的小结页写法不要一个样。

## 四、找出藏着的中间层

一章的正文超过 6 页，或章内一组内容超过 5 项，通常是两层内容被压成了一层。找一个分组维度，把它们分成两到四组，每组一句概括。

例：一章列了八个功能页。按“谁在用”分成客户端、业务员端、管理端三组，章内多出一层，每组可以有一页总览带出后面的展开页。

项数由事实决定的内容不在此列：流程本来有七步、状态本来有九个，就照实写，可以按阶段分组，组内保留每一项。

层级多不等于页数多。一页总览可以同时承载父节点和它的几个子节点，后面只展开需要细讲的那几个。

一章只有一页时，把它并到相邻的章。

## 五、同一概念只在一处展开

同一个概念、功能或数据只在一页讲透。别的页用到它，只提一句并注明见哪页。在每页的 `expands` 里登记本页展开的概念，脚本会查重。

## 六、章一级扁平的征兆

| 征兆 | 改法 |
|---|---|
| 章名是“背景、现状、方案、计划”，说不出章论点 | 回到 `L1-deck.md` 第二节换一种分章办法 |
| 章内的页是同类东西的罗列，功能一到功能十 | 按第四节加一层，或改用“总览展开” |
| 删掉章内任意一页，其他页不受影响 | 页与页之间缺支撑关系；重选组织模式 |
| 每页看起来同等重要 | 标出主干页和支撑页；支撑页压缩或进附录 |
| 每章的排法完全一样 | 按各章内容各选模式；内容确实同构时保留 |

## 七、这一层的自检

对每一章问三件事：

- 只读本章各页的标题，能不能得出章论点。
- 每页在所选模式里是哪一步，有没有多余的页或缺的页。
- 这一章回答的是听众的问题，还是讲者想讲的内容。
