# 页面内容规划：把一页写满、写准

写每页内容之前读这份文件。它管一件事：一页上放哪些内容、摆成什么样。规则在 `L3-slide.md` 和 `L4-block.md`，这里讲做法。

一页只有三四句短语，排出来就是三四个空框。内容丰富靠的是把每个对象展开到听众会追问的几个方面，不靠多写字，也不靠加修饰。

## 一、四步规划

### 1. 定对象

这页讲的是哪几个东西：几个步骤、几层、几个方案、几个阶段、几个问题、几类人。一般 2 到 6 个。对象就是图示里的“项”。

### 2. 定方面

听众看到每个对象会追问什么，就按那几个问题展开。选 2 到 3 个方面，全页的对象用同一组方面，这样能排成整齐的行和列。

| 这页在讲 | 常用的方面 |
|---|---|
| 进展、成效 | 做了什么；做到什么程度（数字）；对单位有什么用 |
| 问题 | 表现；影响（数字或事例）；原因；打算怎么办 |
| 方案、做法 | 做什么；谁来做；要什么条件；怎么判断做成了 |
| 几个方案比较 | 代价；效果；风险；退路 |
| 计划、阶段 | 做什么；完成标准；负责人或时间；停止条件 |
| 机制、架构 | 管什么；输入和输出；谁在用 |
| 风险 | 什么情况下会出事；出了事怎么发现；怎么纠正 |
| 概念、方法（培训） | 是什么；怎么做；一个例子；常见错误 |
| 对客户的方案 | 客户现在的做法；我们的做法；客户得到什么 |

方面的名称就是表头或行名，写一次。写进内容块的 `columns`。

### 3. 回材料取内容

对象和方面定了，就得到一张格子表。回到材料里逐格取内容：

- 每格一句具体的话，带名称、数字或例子。“优化流程”是空话，“月底三天的单据提前到 25 号分批提交”是内容。
- 材料里取不到的格：整个方面都取不到就删掉这个方面；个别格取不到就写“待定”或“无”，不编。
- 取完后看这张表：格子多数是空的，说明方面选错了，换一组方面，或把这页和相邻页合并。
- 每格按要说的内容写足，一般 15 到 40 个字。排版时放不放得下不在这一步考虑：字号由绘图库自动调，实在放不下就拆页。为了放得下把“有版面几何和表格算术检查，不查结构”压成“不查结构”，听众就不知道它查了什么。

写法是每项一个 `name` 加一组 `cells`，`cells` 与 `columns` 一一对应：

```json
{"relation": "顺序", "component": "分阶段流程", "says": "分三个月上线，每个月结束时按约定条件决定是否往下走",
 "columns": ["做什么", "进入下一步的条件"],
 "items": [
   {"name": "第 1 个月 并行比对", "cells": ["系统与人工各审一遍，逐单比对结论", "结论一致的比例达到约定值"], "mark": "当前"},
   {"name": "第 2 个月 小范围切换", "cells": ["两个部门改用新流程，其余部门照旧", "差错单据数不高于人工审核时期"]},
   {"name": "第 3 个月 评估", "cells": ["汇总到账时间、差错和催办次数", "由财务负责人决定是否推广"]}
 ]}
```

`mark` 标出要让听众先看到的那一项，例如当前阶段、推荐方案。页面上用底色或位置突出它，不另外贴字。

### 4. 加支撑块

主块之外，最多再加两个支撑块。只加能让论点更站得住的：

- 关键数字：2 到 4 个，每个带一句含义。适合进展、成效、问题的规模。
- 一个具体例子：一张单据、一个客户、一次事故，写清经过和结果。
- 前后对比或与别人的对比：同一个量的两个值。
- 听众常提的疑问和回答。
- 口径和边界：数据的时间范围，结论在什么条件下不成立。

材料里没有这些就不加。不为了填满页面而加。

## 二、版面原型

按内容选一种原型，写进这页的 `layout` 和各块的 `component`。括号里是 pptkit 的画法。

| 原型 | 适合 | 主块 | 支撑块 |
|---|---|---|---|
| 对象乘方面的表 | 几个对象、每个有两三个方面要说 | 对照表（`matrix`），第一列是对象，要突出的一列加底色 | 无，或表下一组短条目 |
| 数字加表 | 进展和成效：先给规模，再给明细 | 对照表（`matrix`） | 表上方一排大数字（`stats`） |
| 阶段表 | 计划、路线、历程 | 分阶段流程（`stages`），当前阶段突出 | 无 |
| 分层加侧栏 | 架构、层级，每层对应一件听众关心的事 | 分层（`layers`） | 右侧与各层对齐的一栏（`side`） |
| 流程加明细 | 步骤，每步有输入、输出或负责人 | 分阶段流程（`stages`）或步骤流程（`flow`） | 无 |
| 两栏对照 | 改前改后、两个方案 | 对照表（`matrix`）按方面逐行对比，或对照栏（`compare`） | 一个强调数字（`callout`）给出差距 |
| 案例 | 用一件具体的事说明做法 | 步骤流程（`flow`）：背景、做法、结果 | 结果的数字（`stats`） |
| 大数字 | 一页只说一个数或一句话 | 大数字（`stats` 或 `callout`） | 无 |
| 架构图 | 一个系统由哪些部分组成、谁在上谁在下 | 分层架构图（`arch`），本期要讲的部分加重 | 无，图例在图的右上角 |
| 流程图 | 一件事怎么流转，有判断、分支、回退，或跨几个角色 | 流程图或泳道流程图（`flowchart`） | 无 |
| 能力地图 | 一批东西的全貌和各自的状态 | 能力地图（`grid`），按状态分两到三档 | 一排大数字给出各档的数量 |

- 几个对象各有两三个方面时，优先用表，不用卡片。表把方面的名称写在表头，只写一次；卡片要在每张卡里重复一遍。
- 相邻两页不用同一种原型。一章里至少有一页不是表，例如流程、分层或大数字。
- 一页的文字量：密度中高的正文页，主块的格子一般在 6 个以上。

## 三、让版面传达信息，不写次要标签

位置、大小、底色已经说明的事，不再用文字说一遍。

| 不写 | 改成 |
|---|---|
| 每格前面的“做法：”“结果：” | 表头写一次“做法”“结果” |
| 每个阶段贴“未开始” | 只把当前阶段用底色标出来 |
| “第一步、然后、最后” | 用箭头和从左到右的顺序 |
| 图示下面的一行说明文字 | 说明写进图示本身，或删掉 |
| 卡片里标题下的灰色小字 | 并进正文，或删掉 |
| “说明”“备注”“小结”“要点”这类栏名 | 直接写内容 |
| 重复标题的导语、重复标题的结论条 | 不写 |
| 每个数字后面都带的同一个单位 | 写在表头里 |
| 与内容无关的英文小标题、图标 | 不加 |

导语和结论条不是每页必有：

- 标题已经是一句完整的论断时，不写导语。导语只在三种情况下写：标题是主题式的，论点要靠导语说出来；需要交代数据口径；图示需要一句读图方式。
- 结论条只在这页的内容推出了标题和导语之外的一句话时写，例如下一步的动作、对听众的请求。
- 整份里写了结论条的正文页不超过一半。改写一份旧大纲时，逐页重新判断这两栏，不沿用旧稿里的。

强调只靠三样：放在最前面或最大的位置、加底色、加粗。一页只强调一处。

## 四、材料本身是一张图时，画全

系统的组成、业务的流转、一批能力或事项的全貌，这三类内容本身就是一张图。拆成几页表格以后，听众看不到整体，也看不出这次讲的部分在整体里的位置。这类页按下面的办法规划，项数按事实列全，不为了少而合并。

**分层架构图**

1. 定层：自上而下，使用方在上，基础在下，一般 3 到 6 层。
2. 列每层的组成。一层超过 8 个时在层内分组。
3. 找贯穿各层的东西，例如安全、运维、标准，放到两侧。
4. 标出这次要讲的部分，例如本期新建的模块，用 `mark` 写上它属于图例的哪一档。

```json
{"relation": "层级", "component": "分层架构图", "says": "平台分五层，本期新建的六个模块集中在应用层和能力层",
 "legend": ["本期新建", "已有"],
 "items": [
   {"group": "渠道层", "items": ["官网商城", "App", "小程序", "门店收银"]},
   {"group": "应用层", "items": [
     {"group": "订单服务", "items": ["下单", "支付", {"name": "退换货", "mark": "本期新建"}]},
     {"group": "仓配履约", "items": ["库存分配", {"name": "门店自提", "mark": "本期新建"}]}]},
   {"group": "数据层", "items": ["订单库", "库存库", "实时数仓"]}],
 "right": {"group": "运维", "items": ["发布", "监控", "应急"]}}
```

**流程图**

1. 列节点，按流程先后排。每个节点写动作，动宾短语，不超过 8 个字。
2. 找判断点。每个判断写成一个问句，并写清每条分支去哪里、线上标什么字。
3. 找回退：哪一步不通过要回到前面哪一步。
4. 几个角色各管一段时，把角色写成泳道，每个节点标明在哪条泳道。
5. 这次要讲的那一步用 `mark` 标出。

```json
{"relation": "分支", "component": "泳道流程图", "says": "主管只审 500 元以上的退款",
 "lanes": ["顾客", "主管", "系统"],
 "items": [
   {"id": "a", "lane": "顾客", "name": "提交退款申请", "kind": "开始", "to": ["b"]},
   {"id": "b", "lane": "系统", "name": "金额超过 500 元？", "kind": "判断", "to": [["c", "是"], ["d", "否"]]},
   {"id": "c", "lane": "主管", "name": "审核通过？", "kind": "判断", "to": [["d", "通过"], ["a", "退回补材料"]]},
   {"id": "d", "lane": "系统", "name": "发起退款", "mark": true, "to": ["e"]},
   {"id": "e", "lane": "系统", "name": "通知顾客", "kind": "结束"}]}
```

**能力地图**

1. 分组：按业务环节或按使用者，3 到 6 组。
2. 每组列全，一项一格，名称不超过 8 个字。
3. 定图例：状态分两到三档，例如已上线、建设中、规划。每项用 `mark` 写它属于哪一档。
4. 标题里说出这张图的结论，例如哪一档有多少、集中在哪一组。

```json
{"relation": "层级", "component": "能力地图", "says": "30 项能力里 9 项已上线，在建的 10 项集中在库存和配送",
 "legend": ["已上线", "建设中", "规划"],
 "items": [
   {"group": "顾客触点", "items": [{"name": "订单查询", "mark": "已上线"}, {"name": "自助退款", "mark": "建设中"}, {"name": "以旧换新", "mark": "规划"}]},
   {"group": "仓配协同", "items": [{"name": "库存同步", "mark": "已上线"}, {"name": "配送调度", "mark": "建设中"}]}]}
```

这三种图的页，标题说结论，图说全貌。图里的名称材料里有什么写什么，材料里没有的模块、步骤、状态不补。图已经很满的页不再加支撑块。

## 五、写完一页后问自己

1. 把这页的文字全部遮住，只看形状和位置，看得出哪一项最重要、几项之间是什么关系吗？
2. 每一格删掉以后，听众会少知道一件具体的事吗？不会就删。
3. 页面上有没有哪句话是在解释版面本身，例如“如下图所示”“以下三个方面”？有就删。
4. 这页比上一页多了什么新东西？说不出来就合并。
