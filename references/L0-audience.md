# 第 0 层 听众：用听众听得懂的角度讲

这一层定定义卡里的听众四项（`audience`）和术语处理（`terms`）。同一份材料，对不同的人要讲的内容和讲法都不同。结构定下来之前，先弄清听众是谁、有什么背景。

## 一、要弄清的四件事

写进定义卡的 `audience`：

- `who`：谁在听，谁拍板。听众不止一类时分出主次。
- `background`：他们的专业和岗位；对这件事已经知道什么、不知道什么。
- `cares`：他们用什么标准判断这件事。常见的有投入产出、风险、进度、合规、对本部门的影响、具体怎么操作。
- `angle`：用什么角度讲他们听得懂。写他们熟悉的业务、说法和参照物。

信息从三处取，按顺序：用户说的；材料里看得出的，例如会议名称、收件人、以往的意见；向用户提问。

听众背景不清楚时必须问用户。其他项缺了可以用场景档的默认值，这一项不行：背景判断错了，后面的结构和用词都会跟着错。问得具体：听众是谁、什么岗位、对这个领域熟悉到什么程度、最在意什么、以前对这件事说过什么。

## 二、把讲者的角度换成听众的角度

讲者习惯按自己做事的过程和内部分工来讲。听众只关心这件事和自己的关系。

| 讲者的角度 | 换成听众的角度 |
|---|---|
| 我们做了哪些功能 | 听众的哪件事因此变了 |
| 技术原理和实现方式 | 做法和结果：能做什么、做不了什么、出错时怎么办 |
| 我方的模块划分和内部分工 | 听众的工作流程，或听众会问的问题 |
| 技术指标和测试得分 | 听众自己的计量：时间、人手、差错、费用 |
| 我们遇到的困难 | 对听众的影响，以及需要听众配合的事 |

不同背景的听众，侧重不同：

- 非本专业的管理者：关心为什么做、投入和回报、风险、需要他做什么。机制少讲，讲清做法和结果即可。
- 业务使用者：关心自己的工作怎么变、怎么操作、出了问题找谁。按他们的工作流程来组织内容。
- 同行专家：关心方法是否成立、和已有做法的差别、证据是否充分。术语可以直接用，证据要细。
- 客户：关心对方是否理解自己的需求、这件事对自己有什么用。用客户自己的说法和材料。

材料常常是写给讲者自己看的，页面上的话则由讲者说给听众听，人称要跟着换。材料里对讲者说的“你”，到页面上是“我”或“我们”。例如材料写“由你盲评排序”，页面写“由我盲评排序”。页面上也不用第三人称称呼听众，例如给副总看的页不写“副总提意见不用懂技术”，写“提意见不用懂技术”。

需要借听众熟悉的事物来说明陌生概念时，类比只用来帮助理解，定义仍用准确的说法，并写明类比在哪一点上不成立。

## 三、术语按听众的熟悉程度处理

把标题、导语和图示里出现的专业词、缩写、英文术语列出来，逐个判断：

| 听众对这个词 | 处理 | 例 |
|---|---|---|
| 日常在用 | 直接用 | 对财务人员说“应付账款” |
| 听过，说不清 | 第一次出现时用半句话解释 | “灰度发布，即先让一小部分用户用上新版本” |
| 没听过 | 换成对做法或结果的描述；必须保留原词时先解释再用 | “CI/CD 流水线”换成“代码提交后自动检查和发布的过程” |

第二、三类登记在定义卡的 `terms` 里，一个词一条，写明原词和处理办法，全稿照此执行。登记为“换说法”的词，页面上不再出现原词；听众日后需要对上原词时，在附录放一张对照表。

## 四、详略跟着听众的已知走

- 听众已经知道的：一句带过，或不讲。
- 听众不知道、后面又要用到的：先铺垫，放在用到它之前。
- 听众不需要知道的：进附录。
- 开头从听众已经了解并认可的事实讲起，再引到新内容。

## 五、听众不止一类

- 定一类主要听众，通常是拍板的人。主线为他服务。
- 其他听众需要的细节放附录，或放在相应页面的次要位置。
- 两类听众差别很大又同场时，例如领导和技术团队，主线讲结论和影响；每章可以留一页细节，并在导语里点明这页面向谁。

## 六、这一层的自检：换成听众的身份再读一遍

读标题串读时，把自己当作听众，问四件事：

- 标题和导语里的每个词，听众都懂吗。
- 每章回答的是听众会问的问题吗。
- 例子取自听众熟悉的领域吗。
- 有没有只对讲者重要、对听众不重要的页。
